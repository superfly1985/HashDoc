# 识档 HashDoc

基于 **SHA-256 哈希**的图纸档案绿色管理工具。文件以内容哈希为唯一身份——改名、移动位置都不会丢失业务属性（供应商、文档类型、各类编号全部跟随档案）。

- 技术栈：C# WinForms（.NET Framework 4.8，Win10 系统自带，无需安装任何运行库）+ SQLite 单文件库
- 部署形态：EXE + 2 个 DLL，整个文件夹约 4 MB，拷贝即用，普通用户权限运行
- 管理类型：PDF / JPG / PNG / BMP / TIF·TIFF（.jpeg 按 JPG 对待，其余后缀自动跳过）

## 构建与自检

```cmd
build.cmd                    REM 开发构建到 out 目录
out\HashDoc.exe --selftest   REM 无界面功能自检，结果见 out\selftest_result.txt
out\HashDoc.exe --dbinfo     REM 打印程序版本 / 数据库位置 / 库版本 / 档案条数
release.cmd                  REM 打发布包 dist\HashDoc_v<版本>.zip（只含程序文件）
```

发布包只包含 `HashDoc.exe`、`HashDoc.exe.config`、`System.Data.SQLite.dll`、`x86\`、`x64\`、`升级说明.txt`，
**不含 data 目录与数据库**——所以解压覆盖程序目录就是升级，档案数据不受影响。

## 发布与升级（覆盖式）

程序和数据是分开的：

```
HashDoc\
  HashDoc.exe  HashDoc.exe.config  System.Data.SQLite.dll  x86\  x64\   ← 程序，可整个覆盖
  data\HashDoc.db                                                      ← 数据，覆盖不碰
  data\backup\HashDoc_db1_20261022_132220.db                            ← 结构升级前自动备份
```

升级步骤：**关闭程序 → 解压发布包覆盖到程序目录 → 双击运行**。三件事由程序自动处理：

1. 老版本的 `HashDoc.db` 若还在 exe 同级，首次运行自动搬进 `data\`，原文件改名 `HashDoc.db.old-<日期>` 留档
2. 库结构需要升级时，先把旧库整份备份到 `data\backup\`，再迁移，并在启动时告知备份路径
3. 若库结构版本比程序新（程序被回退成旧版），直接弹提示并**不写库**，避免旧程序写坏新结构

版本号只有一处来源：`src/HashDoc.csproj` 的 `<Version>`。发布脚本读它来命名压缩包；主窗口标题栏和【设置】页显示同一个版本号，覆盖后一眼能核对是否升级成功。

## 快速上手

1. 【数据维护】在"归档目录"清单里添加归档目录（**可以添加多个不同位置**，如本机盘 + 共享盘；清单第一行为默认入库位置）→ 维护供应商清单：可以逐条新增，也可以用【从文件清单导入供应商…】一次性从 Excel 另存的 CSV 灌入（文档类型已内置 BMG / PPAP / ELV，细分型号如 PPAP-首页 可自行添加）
2. 【文件入库】选择或拖入文件（支持多选）→ 选供应商、文档类型 → 录入 BMG 号 / 供应商零件号 / VW客户号 / ident内部件号 → 开始入库
   - 文件在 `02 BMG\<供应商>\` 下时**供应商自动按目录默认**（仅限字典里已有的名字；一次选的所有文件推得一致才填，不覆盖你已选的），日志里会注明"可改"
   - **源文件本来就在归档目录里**（有人手工拷进去的）→ 直接登记建档，不再复制出 `xxx_1.pdf` 副本
   - **供应商与三类编号都支持随动检索**：打字即弹出库内已有的值，选中或回车即录入，不用记全名
   - 文件自动归档到 `归档目录\供应商名称\`，文件夹自动创建
   - 登记了多个归档目录时，入库窗口顶部出现"归档到"下拉，选哪个就进哪个目录；单目录时该下拉自动隐藏，操作与原来一致
   - 同名文件冲突自动加 `_1`、`_2` 后缀，**绝不覆盖**
   - 已归档过（哈希相同）的文件提示已归档并复用原有属性
   - 默认复制源文件；勾选"移动"则导入后删除源文件
3. 【目录扫描】核对磁盘与档案库：
   - **打开软件会自动检查一次**：只找"归档目录里有、库里没有"的新文件（有人直接拷进去的情况），发现后工具条亮起橙色按钮「发现 N 个新文件 → 补入库」，点一下批量登记；全程只读，不会改动库内任何记录，也不会弹框打断。【刷新】也会重新检查一次
   - **路径、大小、修改时间都没变的文件直接跳过哈希**，只对新增/可疑文件算 SHA-256，所以日常扫描很快
   - 识别结果五类：路径变更（改名/移动）、源文件丢失、重复文件、未入库、内容已变化
   - 扫描范围可选：全部归档目录 / 单个目录（多目录时出现下拉，窗口内列出当前目录清单）
   - 扫描模式二选一：自动静默更新路径 / 列出差异确认后更新（模式持久保存）
   - 源文件丢失：库记录保留并标记【丢失】，不删除档案；文件回归后扫描自动恢复正常
   - 未入库文件（有人手动拷进归档目录）→ 点【补入库】批量登记：**路径在 02 BMG 下一层的自动按目录默认供应商**（仅限字典里已有的名字，字典外留空不猜），其余逐行指定或按路径筛选后"批量设置供应商"统一填；单元格打字有候选；**供应商可以全留空，先入库、事后再补**——主列表会用橙色「待补」标出来，勾上工具条的「只看待补」就能挑出来逐个【编辑档案】补填；手打的新供应商会问一句要不要一并加进字典；**内容与已有档案相同的行自动跳过，不再弹"入库失败"**
4. 【档案检索】全部走数据库索引，不遍历磁盘。文件名模糊 + 供应商 + 文档类型 + 三类编号自由组合；双击打开文件，右键打开所在文件夹 / 编辑档案 / 复制路径 / 复制 SHA-256
   - 左侧目录树按归档目录分组：每个目录一个顶级节点（悬停显示完整路径）；不在任何归档目录内的档案汇总在灰色"（其他位置）"节点
   - 列表把关联号拆成"零件号 / VW号 / ident号"三列，外加 BMG 号一列；窗口变窄时按优先级自动隐藏"大小""类型""BMG号"三列，保证文件名与三类编号始终可见
   - 最左一列「待补」：供应商、文档类型、BMG 号任一为空时显示橙色「待补」（鼠标停上去能看到缺哪几项），工具条勾上「只看待补」就只留这些档案；状态栏始终显示待补总数与缺项明细（如"缺供应商 3，缺BMG号 12"）
5. 【数据维护】备份数据库：单文件库备份就是另存一份，建议定期执行

### 存量目录迁移（一次性初始化）

把已有的深层目录树（如 `S:\QA\quality.dir\1 SQ+IQC\14 供应商前期报告\`）纳入管理：

1. 【数据维护】在归档目录清单里添加 `S:\QA\quality.dir`（清单里若已有别的目录，选中它点"设为默认"）
2. 【数据维护】→【从文件清单导入供应商…】：选一份文件清单（Excel 另存的 CSV，或每行一个完整路径的 TXT），程序只认**「目录标记」紧邻的下一层文件夹**（默认标记 `02 BMG`）——实测 `02 BMG` 下一层就是供应商，其它类型目录层级不一致不自动猜；直接散落在该目录下的文件（`Thumbs.db`、`new folder 1.zip`、`xx模板.xlsx`）自动忽略。候选默认全勾，确认后才写字典
3. 【数据维护】→【按路径规则补齐文档类型…】（手动触发，非自动）：规则为路径中文件夹 `02 BMG`→BMG、`03 ELV`→ELV、`04 PPAP`→PPAP；预览命中清单、默认只勾选类型为空的档案，确认后写库
4. 【目录扫描】首次扫描 → 28,000+ 文件全部进入"未入库" → 选中整批【补入库】：可以先把供应商全部留空入库（几万个几秒登记完），再回主列表勾「只看待补」按目录分批筛、用"批量设置供应商"补；要精确到行时也能逐行打字填

**为什么不再按路径自动猜供应商**：`02 BMG` 下一层确实是供应商，但 `03 ELV` 下一层混着分类目录、`04 PPAP` 下一层是 `PPAP(完整）`/`Supplier PPAP Report` 这类结构性文件夹，各类型目录层级不一致，靠"在路径任意层级匹配供应商名"必然命中分类目录。所以路径匹配已整体删除，供应商只来自字典 + 人工确认。

清单文件（`file-list.csv`）只用于这一次性导入，**不进发布包**，也不需要留在程序目录里。

### 文件命名小提醒

文件名或路径带多余空格（如 `" \ xxx.pdf"`）不影响入库，但可能影响检索命中率，建议有空时清理。

## 业务规则

1. 文件身份 = SHA-256 哈希；文件名、路径只是附属信息
2. 所有归档文件必须存放在已登记的某个归档目录内（可登记多个，互不嵌套；嵌套时取最具体的那个）；外部文件只能通过入库导入
3. 一个档案可绑定多条供应商零件号、多条 VW客户号、多条 ident内部件号；BMG 号是单值字段（可空）
4. 编辑档案只修改数据库元数据，不动磁盘文件
5. 供应商改名会同步更新库内所有档案的供应商字段；磁盘上旧文件夹不自动改名（扫描会跟踪实际路径），下次归档自动使用新文件夹名
6. 供应商/文档类型被档案引用时不可删除，需先处理引用

## 数据说明

| 文件 | 说明 |
|---|---|
| `HashDoc.exe` | 主程序（Win10 自带 .NET 4.8 运行时） |
| `System.Data.SQLite.dll` + `x64/x86/SQLite.Interop.dll` | SQLite 驱动（含 32/64 位原生库） |
| `data\HashDoc.db` | 数据库（档案 + 字典 + 配置都在这一个文件里），首次运行自动创建 |
| `data\backup\` | 结构升级前自动备份的旧库 |

注意：请勿把程序放在 `Program Files` 等需要管理员权限的目录运行（数据库要写到程序目录下的 data 目录）；万一目录只读，程序会退回到 `%APPDATA%\HashDoc\HashDoc.db` 并在【设置】页显示实际位置。


### 表结构（PRAGMA user_version = 3）

```sql
FileInfo(FileHash TEXT PRIMARY KEY,   -- SHA-256，文件唯一身份
         CurrentPath, FileName, FileSize,
         FileMTime TEXT,              -- ISO8601 'yyyy-MM-dd HH:mm:ss'
         Supplier, DocType,
         BmgNo TEXT,                  -- BMG 号（v3 新增，单值、可空）
         Status INTEGER DEFAULT 0,    -- 0=正常 1=源文件丢失
         ImportTime TEXT)
FileCode(FileHash, CodeType,          -- SupplierPartNo / VWNo / IdentNo
         CodeValue, PRIMARY KEY(FileHash, CodeType, CodeValue))
SupplierDict(SupplierName PRIMARY KEY, Remark)
DocTypeDict(DocTypeName PRIMARY KEY, SortOrder, Remark)   -- 首版内置 BMG/PPAP/ELV，可继续添加细分型号
ArchiveRoot(RootPath TEXT PRIMARY KEY, -- 归档目录清单，SortOrder=1 为默认入库位置
            SortOrder INTEGER, Remark)
Config(Key PRIMARY KEY, Value)        -- 扫描模式 / 入库方式等
```

版本迁移自动完成：v1 的单条 `Config.RootDir` 在打开旧库时被搬进 `ArchiveRoot`（作为 SortOrder=1）；v2→v3 给 `FileInfo` 加 `BmgNo` 列。无需手工处理，旧库直接可用。迁移前会先把旧库备份到 `data\backup\`（文件名带起始版本号与时间）；若库版本高于程序支持（回退了旧程序），程序拒绝打开并提示，不会写坏数据。

### 目录扫描的判定逻辑

| 磁盘情况 | 判定 | 处理 |
|---|---|---|
| 路径、大小、修改时间与库内一致 | 未变化 | 跳过哈希，不处理 |
| 同路径但大小/时间变了 | 重算哈希 | 哈希没变 → 静默修正属性；哈希变了 → 内容已变化，人工核对 |
| 库内无此路径，但哈希在库且原路径已不存在 | 档案被移动/改名 | 自动模式直接更新路径；确认模式列出待勾选 |
| 库内无此路径，哈希在库且原路径还在 | 重复文件 | 列表展示，可右键删除磁盘副本（档案保留） |
| 哈希不在库 | 未入库文件 | 可补入库（批量登记，不复制文件） |
| 库内记录在磁盘上找不到 | 源文件丢失 | 标记 Status=1，记录永久保留 |
